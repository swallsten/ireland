# Ireland itinerary, 1 to 8 September 2026

A single-page, passphrase-protected itinerary for GitHub Pages, with a comment
thread on every section so the five of you can leave notes for each other.

No server, no build pipeline, no npm. Two files get published: `index.html` and
`payload.json`.

---

## How the protection actually works

This is not a JavaScript `if (password === "...")` check, which anyone defeats by
opening View Source.

The itinerary is encrypted before it ever reaches GitHub. `payload.json` holds
AES-256-GCM ciphertext. The key comes from your passphrase through PBKDF2-HMAC-SHA256
at 300,000 iterations with a random salt. The browser derives the key with WebCrypto
and decrypts in memory when someone types the passphrase.

What that buys you: **`payload.json` is noise without the passphrase.** Even if the
repo is public and someone finds the URL, there is nothing readable in it. Your house
names, your dates and the fact that your homes are empty are not sitting in a public
file.

Your Supabase keys are inside the encrypted payload too, so only people with the
passphrase can post notes.

What it does not buy you: anyone you give the passphrase to can read everything and
extract those keys. It protects against strangers, not against the five of you. That
is exactly the threat you described.

## What is in this folder

| File | Commit it? | What it is |
|---|---|---|
| `index.html` | yes | The shell. Passphrase gate, comment UI, all the CSS. |
| `payload.json` | yes | The encrypted itinerary. Regenerated by `build.py`. |
| `shell.html` | yes | Template `build.py` uses to write `index.html`. |
| `build.py` | yes | Encrypts the itinerary and writes `index.html`. Holds no secrets. |
| `supabase.sql` | yes | Paste into Supabase to create the notes table. |
| `.gitignore` | yes | Keeps the two files below out of the repo. |
| `source/itinerary.html` | **NO** | The plain itinerary. Keep it locally. |
| `source/config.json` | **NO** | Your Supabase keys. Keep them locally. |

`.gitignore` already excludes `source/`. Do not remove that line. If `source/` ever
gets committed, the encryption was pointless.

Keep a backup of `source/` somewhere that is not the repo. It is the only copy of the
editable itinerary.

## Step 1: get it online (10 minutes)

1. Create a new repository on GitHub. Name it something boring, `ireland-2026` is fine.
   Public or private both work, since the content is encrypted either way.
2. Drop the contents of this folder into it and push:

   ```bash
   cd <this folder>
   git init
   git add .
   git commit -m "Ireland itinerary"
   git branch -M main
   git remote add origin git@github.com:YOURNAME/ireland-2026.git
   git push -u origin main
   ```

   Run `git status` before that first commit and confirm `source/` is **not** listed.

3. On GitHub go to **Settings → Pages**. Under "Build and deployment", set Source to
   **Deploy from a branch**, branch `main`, folder `/ (root)`. Save.
4. Wait about a minute. Your URL will be
   `https://YOURNAME.github.io/ireland-2026/`.
5. Open it. It should ask for the passphrase, which lives in `source/config.json`
   under `"passphrase"`. Changing it is Step 3.

At this point the page works and the notes are switched off.

---

## Step 2: switch on the notes (10 minutes)

1. Go to [supabase.com](https://supabase.com) and sign up. Free tier, no card.
2. **New project.** Any name. Pick the region closest to you, not to Ireland.
   Set a database password and save it somewhere, though you will not need it again.
   It takes a couple of minutes to spin up.
3. Open **SQL Editor** in the left sidebar, click **New query**, paste the entire
   contents of `supabase.sql`, and press **Run**. You should see "Success".
4. Go to **Project Settings → API**. Copy two things:
   - **Project URL**, which looks like `https://abcdefgh.supabase.co`
   - the **anon** / **public** key, a long string starting `eyJ...`

   Take the **anon public** key, not the service role key. The service role key
   bypasses all the security rules and must never go in a web page.
5. Paste both into `source/config.json`:

   ```json
   {
     "supabaseUrl": "https://abcdefgh.supabase.co",
     "supabaseAnonKey": "eyJhbGciOi...",
     "passphrase": "your real passphrase"
   }
   ```

   The `passphrase` key is what `build.py` uses when you run it with no arguments.
   It stays in this gitignored file and is never written into the payload.

6. Rebuild and push:

   ```bash
   python3 build.py
   git add index.html payload.json
   git commit -m "Switch on notes"
   git push
   ```

7. Reload the page, unlock it, and open any section's **Notes**. Post one. If it
   appears, you are done.

Then text four people the URL and the passphrase.

## Step 3: change the passphrase

`dogsbay` is a placeholder. Pick something you are happy texting to four people.

```bash
python3 build.py --passphrase "your new passphrase"
git add index.html payload.json && git commit -m "New passphrase" && git push
```

Anyone already on the page keeps working until they hit **Log out** or clear
their browser data, then they need the new one.

To make it permanent, put it in `source/config.json` under `"passphrase"` (see
Step 2). That file is gitignored, so the passphrase never reaches GitHub.

**Do not put the real passphrase in `build.py`.** `build.py` is committed, so on a
public repo that would publish the passphrase in the same repo as the
`payload.json` it decrypts, defeating the encryption entirely. `build.py` now
refuses to build with the `dogsbay` placeholder rather than silently reverting.

## Updating the itinerary later

Edit `source/itinerary.html`, then:

```bash
python3 build.py
git add index.html payload.json && git commit -m "Update" && git push
```

Notes are keyed off each section's heading, so if you rewrite a heading, the notes
attached to that section move into the **Notes for the group** thread rather than
disappearing. Renaming a day like "Saturday 5 September" would orphan its notes, so
leave those alone.

## How the notes behave

- Every day and every reference section gets its own thread. There is a general
  thread at the top for anything else.
- People type a name once. The browser remembers it, and **Change name** in the top
  bar resets it.
- The page re-checks for new notes every minute while the tab is open, and
  **Refresh notes** forces it.
- Nobody can edit or delete a note from the page, deliberately, so a stray tap cannot
  wipe the thread. To remove something, delete the row in Supabase under
  **Table Editor → comments**.
- Once unlocked, the decrypted page is cached in the browser, so it still opens with
  no signal. Notes need a connection. **Log out** clears that cache.

## Things worth knowing before you rely on it

- **Supabase pauses free projects after about a week with no activity.** If you set
  this up now and nobody touches it until 1 September, it may be asleep when you need
  it. Post a note every few days, or be ready to hit Resume in the dashboard. This is
  the single most likely thing to go wrong.
- **Connemara signal is patchy.** The cached page opens offline, the notes do not.
  Keep the PDF as the real offline copy.
- **The PDF is not encrypted**, so do not commit it to this repo. `.gitignore`
  already blocks `*.pdf`.
- **Anyone with the passphrase can extract the Supabase anon key** from the payload.
  With the rules in `supabase.sql` the worst they could do is add rows to the notes
  table. If that ever became a problem, rotate the key in Supabase and rebuild.
- **GitHub Pages is public hosting.** The `noindex` tag asks search engines to stay
  away and they generally comply, but the encryption is what actually protects you.

## If something is wrong

**The passphrase is rejected.** The build and the page must match. Rerun `build.py`
with the right passphrase and push, then hard-reload the page.

**"Notes are not switched on yet."** `source/config.json` was empty when you last ran
`build.py`. Fill it in and rebuild.

**"Cannot reach the notes right now."** Usually a paused Supabase project. Open the
dashboard and resume it. Otherwise re-check that you pasted the anon key and not the
service role key, and that `supabase.sql` ran without errors.

**Page is blank after unlocking.** Open the browser console. If `payload.json` 404s,
it did not get pushed, or Pages has not rebuilt yet.
